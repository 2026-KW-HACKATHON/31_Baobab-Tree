# 월계1동 주민 참여형 설문·실험 통합 플랫폼

## 1. 프로젝트 개요

### 프로젝트 한 줄 설명
대학생·지자체·지역 상인이 필요한 설문이나 실험 참여자를 모집하고, 월계1동 주민은 다양한 조사에 참여한 뒤 포인트나 지역 혜택을 받을 수 있는 **지역 기반 주민 참여 플랫폼**.

### 프로젝트를 생각하게 된 배경
현재 대학생이나 대학원생이 설문조사, 인터뷰, 실험 참여자를 모집할 때 에브리타임, 학교 커뮤니티, SNS 등에 각각 모집글을 올리는 경우가 많다.

지역 상인 역시 신메뉴, 영업시간, 서비스 개선 등에 대해 고객 의견을 받고 싶어도 체계적으로 조사하기 어렵고, 지자체에서도 주민 의견을 수렴하기 위해 설문을 진행하지만 주민들이 관련 설문이 진행되고 있다는 사실을 알기 어려운 경우가 있다.

반대로 주민 입장에서는 참여할 수 있는 설문과 지역 활동 정보가 여러 곳에 흩어져 있고, 설문에 참여하더라도 특별한 보상이 없는 경우가 많다.

따라서 **설문을 한곳에 모아 주민에게 제공하고, 참여에 대한 소정의 보상을 지급하는 구조**를 만들어 참여율을 높이는 것을 목표로 한다.

# 2. 해결하려는 문제

### ① 조사자는 참여자를 구하기 어렵다
대학생, 연구자, 지자체, 지역 상인이 설문이나 실험 참여자를 모집하려면 여러 커뮤니티에 직접 홍보해야 한다.

### ② 주민들은 참여할 설문을 찾기 어렵다
주민 의견을 묻는 조사들이 여러 사이트나 커뮤니티에 흩어져 있다.

### ③ 설문 참여 동기가 부족하다
설문에 참여해도 주민에게 직접적으로 돌아오는 혜택이 거의 없다.

### ④ 지역 주민 데이터를 얻을 수 있는 통합된 창구가 없다
특정 지역 주민을 대상으로 빠르게 의견을 수렴하고 결과를 확인할 수 있는 플랫폼이 부족하다.

# 3. 서비스 핵심 구조

서비스 이용자는 크게 세 그룹으로 나눈다.

| 사용자 | 예시 | 주요 기능 |
|---|---|---|
| 참여자 | 월계1동 주민 | 설문 검색, 참여, 포인트 적립 |
| 조사 등록자 | 대학생, 연구자, 가게 사장, 지자체 | 설문 등록, 대상 설정, 결과 확인 |
| 관리자 | 플랫폼 운영자 | 설문 승인, 신고 처리, 포인트 관리 |

서비스 흐름은 다음과 같다.

**조사 등록자**

설문 등록  
→ 참여 조건 설정  
→ 모집 인원 및 보상 설정  
→ 설문 게시  
→ 주민 참여  
→ 결과 및 통계 확인

**주민**

회원가입  
→ 지역 및 기본 정보 설정  
→ 참여 가능한 설문 확인  
→ 설문 참여  
→ 참여 완료  
→ 포인트 지급  
→ 포인트 사용

# 4-4. 설문 방식

설문은 두 가지 방식을 지원하는 방향으로 개발한다.

### 방법 1. 외부 설문 링크 등록

Google Forms, Microsoft Forms 등의 URL을 등록한다.

플랫폼에서 설문 소개 확인  
→ 참여하기 클릭  
→ Google Forms 이동  
→ 설문 참여

이 방식의 장점은 설문 제작 기능을 처음부터 전부 개발하지 않아도 된다는 것이다.

단, 외부 설문은 실제 제출 여부 확인과 포인트 자동 지급이 어려울 수 있기 때문에 MVP에서는 **참여 완료 버튼 + 중복 참여 제한 방식**을 사용할 수 있다.

### 방법 2. 플랫폼 자체 설문

플랫폼 내부에서 간단한 설문을 제작한다.

1차 구현 항목

- 객관식
- 복수 선택
- 주관식

정도만 지원한다.

# 5. 포인트 시스템

주민 참여를 유도하기 위한 핵심 기능이다.

설문마다 등록자가 참여 보상을 설정한다.

예시

| 활동 | 포인트 |
|---|---:|
| 간단한 설문 | 100P |
| 일반 설문 | 300P |
| 긴 설문 | 500P |
| 오프라인 실험 참여 | 1,000P |

설문 완료 시

**설문 참여 완료 → 참여 내역 생성 → 포인트 지급**

형태로 처리한다.

동일 사용자가 같은 설문에서 포인트를 여러 번 받을 수 없도록 중복 참여도 막는다.

---

# 6. 포인트 사용 방법

해커톤 MVP에서는 실제 결제까지 구현할 필요는 없다.

마이페이지에서

**현재 보유 포인트 : 2,300P**

정도로 보여주고, 가상의 지역 혜택 화면을 구성한다.

예시

- 월계동 OO카페 아메리카노 500원 할인 : 500P
- OO분식 1,000원 할인 : 1,000P
- 지역 문화 프로그램 우선 신청권 : 1,500P

실제 서비스로 발전한다면 지역 상점과 연계하여 포인트를 쿠폰으로 교환하는 방식으로 발전시킬 수 있다.

이 기능이 들어가면

**주민 참여 → 포인트 → 지역 상점 사용**

구조가 만들어져 서비스의 차별성이 커진다.

# 17. 발전 아이디어

## ① AI 설문 생성

조사자가

“20대 주민들이 월계동에서 어떤 문화시설을 원하는지 조사하고 싶다.”

라고 입력한다.

AI가 자동으로

1. 월계동에서 가장 자주 이용하는 문화시설은?
2. 추가로 필요하다고 생각하는 시설은?
3. 문화시설 이용 빈도는?
4. 문화시설 이용 시 가장 중요하게 생각하는 요소는?

# 18. 이 서비스의 차별점

단순히

**“설문을 만들 수 있는 서비스”**

로 접근하면 Google Forms 등 기존 서비스와 경쟁해야 한다.

우리가 강조할 부분은 설문 제작 도구 자체가 아니다.

### 기존 설문 서비스

설문 생성  
→ 링크 생성  
→ 직접 사람들에게 배포

### 우리 서비스

설문 등록  
→ 조건에 맞는 지역 주민에게 노출  
→ 주민 참여  
→ 포인트 지급  
→ 지역 혜택 사용  
→ 지역 데이터를 축적

즉,

**설문 제작보다 ‘참여자 모집과 주민 참여’를 해결하는 플랫폼**

이라고 정의한다.

# 19. 해커톤 발표 핵심 메시지

### 문제

지역 주민의 의견이 필요한 사람은 많지만 참여자를 구하기 어렵다.

### 해결

지역에서 진행되는 다양한 설문과 실험을 하나의 플랫폼에 모은다.

### 참여

주민은 자신에게 맞는 설문에 참여한다.

### 보상

참여에 대한 포인트를 받는다.

### 지역 환원

포인트를 지역 상점이나 지역 혜택에 사용할 수 있다.

### 결과

대학생은 연구 참여자를 얻고,  
지역 상인은 고객 의견을 얻고,  
지자체는 주민 데이터를 얻고,  
주민은 자신의 의견을 전달하고 혜택까지 얻는다.

# 20. 최종 서비스 방향

서비스의 핵심은

**“설문조사 플랫폼”이 아니라 “지역 주민 참여 플랫폼”**

으로 잡는다.

초기에는 월계1동을 대상으로 서비스를 검증하고,

**월계1동 → 노원구 → 서울시 자치구 → 전국 지역 커뮤니티**

순으로 확장할 수 있는 서비스로 설정한다.

최종적으로는

**지역 주민의 의견이 필요한 곳과 의견을 내고 싶은 주민을 연결하고, 참여에 대한 혜택이 다시 지역사회로 돌아오는 구조**

를 만드는 것을 목표로 한다.
